# Corrections

What turned out to be true where the plan said otherwise. This doc outranks the plan ([roadmap.md](roadmap.md), and the milestone plans [migration-plan.md](migration-plan.md) and [ui-migration-plan.md](ui-migration-plan.md)), and each correction has a row in the banner at the top of [roadmap.md](roadmap.md). When a fact in the plan turns out to be wrong, write it here with its date and how it was found, add its row to that banner, and say so in your report; the plan's own text stays as it was written, with the old claim struck through where a reader might still trust it.

| # | Found | The plan said | What is true |
| --- | --- | --- | --- |
| C1 | 2026-10-19, an audit of M10 | M10's dashboard: Phases 1 to 5 complete, with 100 % shadow parity and the trainer and the editor in route bundles of their own | It overstated them. The parity check compared only the fire rate, the multiplier and the x and y arrays, with the same default on both sides, so it reported 100 % while 11 weapons differed; the database round trip dropped fields and re-sorted `specs.json`; and every page still loaded `bundle.js`, the trainer and the editor together. All of it was fixed and tested in M10's Phase 7 ([migration-plan.md](migration-plan.md), *Audit Log*). |
| C2 | 2026-10-21, measured with tracemalloc | M10 1.4: the streaming video decoder holds under 60 MB per clip | Not achievable with full-resolution frames: the peak is 328 MB on a 5 s 1080p clip, constant with the clip's length (the decoder before it held 632 MB of gray frames alone, growing with the clip). |
| C3 | 2026-10-21, a browser check | M10's audit log: `client/storage.ts` registered every attribute twice | A misreading of overlapping output: there was a single `allAttributes.push`, and one keydown handler per numeric input. |
| C4 | 2026-10-23, while building M11 2.5 | M11 2.5: a Vite SSR build writes the trainer into `index.html`, `index-ru.html` and `index-zh-CN.html`, which Express and the static build serve | The SSR build goes to `dist-ssr/`, and the server renders every page with its own `site.json` values when it starts and serves them from memory; `pnpm static` writes a folder per page, and keeps `index-ru.html` and `index-zh-CN.html` for servers set up for them. |
| C5 | 2026-10-23, while adding the first-load test | The first loads reported for M11 until then, in kB | They were KiB (bytes / 1024) labeled kB, 2.3 % below the figure in kB: the Russian and Chinese trainer pages were at 201.6 and 201.0 kB, over the 200 kB budget. The budget test measures kB of 1000 bytes, the stricter reading. |
| C6 | 2026-10-24, building the Studio | M11 1.3: collapsible, form, sheet and sidebar wait for the Studio's shell | The Studio needed none of them, and they were deleted in Phase 5 (5.1); the shadcn CLI adds one back when a page needs it. |
| C7 | 2026-10-24, removing leftovers | M11 3.5: the weapon manager's spec form is built with React Hook Form and zod | No part of the Studio uses React Hook Form: `react-hook-form` and `@hookform/resolvers` were deleted in Phase 5 (5.1), since nothing imported them. |
